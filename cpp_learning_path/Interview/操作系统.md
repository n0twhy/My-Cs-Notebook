# 进程与线程
## 用户态 内核态
为了安全性，稳定性，隔离性
- 内核态：cpu可以执行所有指令和访问所有硬件资源，拥有极高的权限
- 用户态：主要用于运行用户程序，权限较低

## 进程  线程  协程
`进程类似于一个车间，线程类似于车间工人，CPU是工人调度器`
- 进程：是操作系统进行资源(内存空间，文件描述符，网络端口)分配的基本单位，拥有独立的栈、堆空间。把物理地址分为若干页，然后进程建立虚拟地址映射这些页

- 线程：进程内的执行单元，操作系统进行CPU调度和执行的基本单位。多个线程共享进程内存，线程之间通信更高效。但是同时可能存在竞争。
同时，线程有自己独立的用户栈和内核栈

每个线程执行到哪里，调用了什么函数，局部变量是什么，返回地址在哪都放在自己的栈里

- 协程：用户态的轻量级线程。调度完全由用户决定，拥有自己的寄存器上下文，与其他协程共享线程的地址空间，无需内核级的上下文切换

### I/O密集 CPU密集
协程适合IO密集，不适合CPU密集，如果CPU密集协程会执行的很慢，影响其他IO，这时候我们还是需要多线程，多进程

## 线程存在的意义
线程之间可以并发运行，共享相同的内存空间
### 多线程的优势 劣势
- 多线程并发进行，提升程序运行的效率
- 劣势是容易出现竞争访问的问题，还可能造成死锁。

## 切换
### 用户态线程切换为什么陷入内核
内核线程由系统调度，用户不能自己决定CPU下一个执行哪个线程
### 线程切换
非常像协程：会保存当前的寄存器信息，私有栈,TCB(线程控制块)作为上下文信息
调度器选择了下一个要执行的线程以后，从该线程保存的上下文信息中继续执行。
### 进程切换
首先进程有五种状态：创建状态，就绪状态，运行状态，阻塞状态，结束状态

- null -> 创建
- 创建 -> 就绪
- 就绪 -> 运行 被调度器选中，分配
- 运行 -> 结束
- 运行 -> 就绪 时间片用完，系统切换此进程为就绪状态，再从其他就绪状态的进程里选一个运行
- 运行 -> 阻塞 请求某个IO事件必须要等待，该进程切换为阻塞状态
- 阻塞 -> 就绪 等待事件完成，回到就绪状态

#### 进程的上下文
由于线程共享一个虚拟的内存空间，所以切换动作是内核只需要把当前线程的寄存器信息和私有栈保存起来就ok
但是进程之间并不共享，他有一个最重要的东西：页表
#### 页表
虚拟内存要找到真实物理地址，要查页表，但是我们需要的时间是一瞬间，所以CPU内部有一个极快的硬件缓存叫TLB(translation lookaside buffer)
当切换进程时，虚拟内存空间完全不一样了，需要将TLB全部清空。新进程刚运行一开始访问TLB都是未命中，所以需要老老实实查页表，直到TLB被重新填满

所以进程的切换效率相对线程来说是极慢的、

## 进程调度的算法
- 先来先服务FCFS
谁先到，服务谁
实现简单，直观
但是会出现长作业堵塞短作业的问题
- 最短作业优先调度 SJF
运行时间短的，先执行
需要提前知道任务运行时间，现实中很难准确预测
而且长作业很可能饿死
- 高响应比优先调度 优先权 = (等待时间 + 要求服务时间) / 要求服务时间
tradeoff，同时照顾长作业和短作业
避免长作业被饿死
- 时间片轮转
每个进程分配一个时间片，到时就切走，排到队尾

## 协程 Coroutine

协程上下文是用户态，非常轻量

## fork
fork由父进程复制出一个子进程
但是不会立刻完整复制物理内存，fork后，父子进程拥有各自独立的虚拟地址空间和页表，但是页表项一开始可以指向相同的物理空间，并标注为只读，如果尝试写，就会引发`缺页异常`，内核为写入方复制一份新的物理页，更新页表映射，所谓COW

`fork` -> `exec` -> `exit` -> `wait`

### `exec`
把当前进程替换为另一个程序
pid_t pid = fork();

if (pid == 0) {
  execlp("ls", "ls", "-l", nullptr);
} else {
  wait(nullptr);
}
shell进程fork子进程
子进程是shell的副本
子进程调用exec，将自己替换为ls程序
父进程shell wait等待执行结束

### `exit`
内核释放资源，但是会保留进程描述符的少量信息，比如Z，使进程暂时成为`僵尸进程`

### `wait`
等待任意一个子进程退出，读取退出状态，内核彻底释放资源


### fork究竟复制了哪些
- 虚拟地址空间(代码段，数据段，堆，mmap，栈)
- 页表：不会完整复制物理内存，而是复制页表，用COW让父子进程暂时共享物理页
- fd
- 执行上下文


### 僵尸进程  孤儿进程
- 父进程与子进程。子进程已经`exit()`资源已经全部释放和析构，但是父进程没有`wait()`来检查子进程的状态，这时候操作系统为了让父进程能感知到子进程的状态，把子进程的状态改为Z(Zombie).后果是为占一个pid号

- 孤儿进程就是，父进程死了，但是子进程还在运行。这是pid为1的"孤儿院院长"就会把这个孤儿进程安排到自己下边

## 多路复用
是一种IO处理方式，是指在一个线程中，可以处理多个socket中的事件，能够资源复用，防止创造过多线程导致上下文切换的开销
### select, poll, epoll
这是三个多路复用的接口
select -> poll -> epoll
本质上是消除三个瓶颈，fd数量限制，全量拷贝，内核O(n)遍历

#### select
将已连接的socket都放在一个fd文件集合，然后把这个集合拷贝在内核里，内核通过遍历来检查事件。如果事件发生，内核标记为可读或者可写，接着再把集合拷贝回用户态里，再遍历一遍找到可读或者可写的socket。

2次遍历，两次拷贝，用bitsmap
#### poll
没有数量限制了
与select大差不差，把bitsmap换成数组的形式了
#### epoll
fd文件集合是以红黑树的形式存储，增删改的复杂度是O(logn)，select和poll每次都要传整个集合，而epoll只需要插入即可
而且有就绪事件链表，不需要再for循环遍历

##### 为什么用红黑树，哈希表不可以吗
哈希表O(1)，但是高并发状态下连接多了，rehash开销太大

##### ET vs LT
- ET：状态切换的时候才触发
- LT：保持在某个状态就会触发

ET在epoll这里要注意，必须一次性全部读完，不然的话里边剩的就再也醒不过来了
ET对比LT的好处：一次全部处理完，可以少几次sys_call，他只在变化时通知一次

## 1GB内存 申请4GB

- malloc(4GB)，操作系统在虚拟地址空间划出这片区域，但在页表中，这块内存的状态位还是未映射

- 当往这片内存写第一个字节的时候，MMU(Memory Manager Unit)查页表，发现是0(未映射)，不对劲！抛出一个硬件异常(缺页中断)。CPU强行进入内核态，呼叫缺页中断处理程序
分配一个Page(通常4KB)空闲的地方，把他分配出来，修改页表，这片4kb内存状态位置1
