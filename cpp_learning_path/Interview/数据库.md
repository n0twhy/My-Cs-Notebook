# 事务 MVCC
## 特性
- A(atomic)原子性，全部操作要么完成，要么不完成，不应该有中间态
- C(consistency)一致性，
- I(isolation) 隔离性  允许多个并发事务进行读写和修改
- D(durability)持久性  事务处理结束后，对数据的修改应该是永久的

## 问题
- 脏读：读到了另一个还没提交的数据
- 不可重复读
- 幻读
| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| RU（读未提交） | 会 | 会 | 会 |
| RC（读已提交） | 不会 | 会 | 会 |
| RR（可重复读） | 不会 | 不会 | 会* |
| Serializable（串行化） | 不会 | 不会 | 不会 |
### 2PL解决方案
加锁，分为growing和shrinking
growing：可以获取任何锁，但不能解锁，解锁立马进入shrinking
shrinking：只能解锁，不能获取任何锁
why：A = 100, B == 100, T1负责A给B转账50，T2负责读总和
T1写完A-50 = 50释放锁， 这时候B = 100，结果T2趁虚而入，读到A+B=150??????这不可能！
T1回来，继续B+50 = 150
that's why
- RU完全不加读锁
- RC读完立马解锁
- RR事务提交才解锁
- serializable就是在RR基础上，Next-Key Lock防止幻读
### MVCC解决方案
- RU 直接读最新的版本
- RC 每个select生成ReadView，同一事务会看到
- RR 事务第一次select生成一个Read View，直接用到事务结束(注意高并发状态，undolog可能你得遍历几千行才能找到对你可见的版本，而RC几乎每次都是新的，不用怎么遍历)
- 串行化：退化2PL

## MVCC
- 每个tuple的背后  都有两个隐藏的trx_id和undolog_ptr
当前 row（最新版本）
├─ DB_TRX_ID = 100  ← 事务 100 改的
├─ DB_ROLL_PTR ──┐
└─ data: name='Bob', age=30
                 │
                 ▼
         undo log record（旧版本）
         ├─ DB_TRX_ID = 80   ← 事务 80 改的
         ├─ DB_ROLL_PTR ──┐
         └─ data: name='Bob', age=25
                          │
                          ▼
                  undo log record（更旧版本）
                  ├─ DB_TRX_ID = 50
                  ├─ DB_ROLL_PTR = NULL（链尾）
                  └─ data: name='Alice', age=20

- 同时会生成一个Read View快照，里面包含creator_id, min_id, max_id, m_ids

以undolog里的版本号作为T
1. T == RV.creator_id        → ✅ 可见（我自己改的）
2. T < RV.min_id              → ✅ 可见（早就提交了）
3. T >= RV.max_id             → ❌ 不可见（在我快照之后才出现）
4. RV.min_id <= T < RV.max_id：
   ├─ T ∈ RV.m_ids           → ❌ 不可见（快照时还活跃）
   └─ T ∉ RV.m_ids           → ✅ 可见（快照时已提交）

# 锁
## 全局锁
数据备份用
## 表级锁
IS,IX,S,X,SIX，即使是MVCC(读写相互不阻塞，写写也是要阻塞的！)
五种粒度的锁，是为了快速判断我对某个表是否能加锁
- IS：要读表中的某些行
- IX：要写表中的某些行
- S：读整个表
- X：写整个表
- SIX(S + IX)：读整个表的同时写几行
## 行级锁
- Record Lock
- Gap Lock
- Next-Key Lock

# 日志
## undo log
原子性的代表，也用于回滚
每当对一条记录进行写的时候，都要记录在undolog里

## redo log
持久性的代表
### WAL Write Ahead Logging
写操作并不是立刻写到disk里边，而是先写日志，然后在合适的时间写会磁盘
## bin log 
和redo有点像，但是这个用于主从复制和备份恢复，是全量日志，保存了所有日志变更的情况，如果写满一页就再开一页继续写，redo是写满一页保存，再从同一页开始写
