## 如果包成一个大事务
- 慢！
- 占锁时间长
- 可能触发超时

所以我们需要分成三个小事务

最常用的方案是本地消息表
1. 写订单数据(业务表)
2. 往一张消息表里插一条记录：下了一单，需要通知营销和资金服务

## 这时候我们可能需要确保幂等性
因为worker重试收到重复消息，写操作不能重复执行

下游服务要维护一张幂等表
message_id (主键/唯一索引) | status | created_at

## 如果其中有一个小事务崩了
我们工业界分布式事务的设计哲学：只许成功，不许失败。失败就重试

## 订单消息怎么知道商家在哪个网关
维护一个注册表(路由表)，注册表里有每个商家对应的网关

## 消息推送链路
```
订单产生
   ↓
查路由表：商家在线吗？
   ├─ 在线 → 直接推送 → 商家ACK确认
   │         ├─ 收到ACK → 完成
   │         └─ 没收到ACK → 写离线消息表，下次重连补推
   │
   └─ 不在线 → 写离线消息表
                ↓
            商家重连 → 拉离线消息 → 推送 → 删除已推送记录
```
