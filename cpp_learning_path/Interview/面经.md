# 你的RPC的M:N体现在哪
"M 个协程分布在 N 个 IO 线程上——每个 TcpConnection 对应 1 个协程（M 随连接数增长），所有协程调度跑在 N 个 IO 线程的 Reactor 里（N 是固定线程数）。但严格讲是 per-thread N:1 调度：协程一旦分配到某个 IO 线程就不跨线程迁移，没有 Go runtime 那种 work-stealing。所以整体呈现 M:N，单线程内是 N:1。"

# 为什么K = 2的时候性能最好
"LRU-K 的核心是区分冷热数据：只被访问 1 次的页大概率是 scan 过路的，不应该留在池子里。K=1 就退化成普通 LRU，无法区分；K=2 用'第二次访问'做冷热分水岭，成本最低、效果最好。K≥3 的话需要记录更多历史时间戳、计算开销大，而且真正热的数据很快就会访问到第 3 次以上，K=2 已经把 80% 的冷热区分做到了。论文里实验结论也是 K=2 最经济。"
